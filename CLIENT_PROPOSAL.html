Users & governance03

Right access for every role

Permissions will be role-based and enforced by the server. Staff members only see and perform functions appropriate to their responsibilities.

Super Admin
Full control of the platform, security, settings, and access.
Administrator
Students, batches, enrolments, operational reports, and accounts.
Academic Manager
Syllabus planning, class completion, approvals, and releases.
Instructor

Content Manager
Uploads, descriptions, ordering, and resource preparation.
Website Editor
Public pages, trainers, testimonials, FAQs, and notices.
Student
Only own enrolments, available classes, content, and progress.

Permission examples

Manage usersAssign rolesCreate batchesEnrol students Plan classesUpload materialsApprove contentComplete class Release materialsView reportsEdit websiteReview audit log
Governance recommendation: for stronger control, uploading content and releasing it can be assigned to different roles. This creates a simple review-and-approval process.

Protection principles

Least access

Give each user only the permissions needed for their work.

Server validation

Hidden buttons are not security; every request is authorized centrally.

Audit history

Record who completed, released, re-locked, or changed important content.

Core business workflow05

Content unlocks only after class

The system supports preparation in advance without exposing future learning materials. Release is explicit, controlled, and recorded.

Controlled material-release journey
1

Plan

Schedule class and define objectives.

2

Prepare

Upload notes and video placeholders. Student access stays locked.

3

Teach

Conduct the live class using the external platform.

4

Confirm

Instructor or manager marks class completed.

5

Release

Approved resources unlock and students are notified.

Manual

An authorized staff member releases the content. Recommended for the MVP.

Scheduled

Approved content unlocks at a defined date and time.

Delayed

Content unlocks a set period after the class is completed.

Rules enforced by the platform

Uploading never means publishing.
Draft classes cannot release resources.
Only authorized roles can confirm completion.
Only approved resources are released.
Students need an active batch enrolment.
Direct links cannot bypass permissions.
Staff may preview locked resources.
Emergency re-lock is available and audited.
Illustrative example: “Technical Analysis — Class 06” is visible on the student's timetable. Its PDF and recording remain locked until the Saturday class is completed and the academic manager presses Release.

Technology & security11

A practical, maintainable foundation

For the current MAMP environment, a Laravel and MySQL application is a natural fit. A unified web application keeps the initial build and deployment straightforward.

Recommended application

  • Laravel backend
  • MySQL database
  • Blade and Livewire interface
  • Responsive component system
  • Queued email notifications
  • CSV/Excel reporting exports

Protected content

  • Private object or video storage
  • Short-lived signed access URLs
  • File type and size validation
  • Active-enrolment validation
  • Streaming preferred for large videos
  • Defined backup and retention policy

Security baseline

Identity

Secure passwords, reset flow, session protection, login throttling, and optional admin 2FA.

Authorization

Server-side roles, ownership checks, active enrolment checks, and protected downloads.

Operations

Error monitoring, audit logs, backups, restoration tests, and production health checks.
